# COHIBA Community Traction Evidence Standard v1.0

## Purpose
Define what counts as real community traction and prevent inflated or unverifiable growth claims.

## Evidence classes

### T1 — Public platform evidence
Examples:
- official X follower/engagement analytics;
- GitHub stars/forks/issues/PRs/contributors;
- public community posts and creator outputs.

Must include:
- source;
- date range;
- screenshot/export or public URL where available;
- paid/organic classification.

### T2 — First-party aggregate website evidence
Examples:
- Community Hub views;
- clicks to official X/GitHub;
- Profile/Whitepaper/Security views.

These are interaction counts only. They do **not** prove unique humans.

### T3 — Contributor evidence
A contributor must have at least one verifiable output:
- artwork/meme/video;
- translation;
- research;
- moderation work;
- GitHub issue/PR;
- security review;
- partner introduction leading to a verified interaction.

### T4 — Retention evidence
Track:
- first contribution;
- second contribution;
- 30-day returning contributor;
- repeat campaign participation.

## North-star metric
**Monthly Active Contributors (MAC)**

MAC must be computed from verifiable contribution records, not follower count.

## Minimum traction pack for fundraising/listing discussions
Prepare a dated evidence bundle containing:
- official X metrics;
- website aggregate funnel metrics;
- monthly active contributors;
- returning contributors;
- community-created assets;
- GitHub activity;
- top referral sources;
- partnership referrals;
- paid vs organic split;
- methodology and known limitations.

## Anti-inflation policy
Exclude:
- purchased followers;
- bots;
- duplicate identities known to be controlled by the same operator;
- incentivized engagement represented as organic;
- fake giveaways;
- wash interactions;
- self-generated circular referral traffic.
