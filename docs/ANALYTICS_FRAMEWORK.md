# COHIBA Analytics Framework v1.0

## Principle
Measure behavior without pretending aggregate clicks are unique humans.

## First-party aggregate events
The website may count allow-listed events such as:
- home_view
- community_view
- community_x_click
- community_github_click
- community_profile_click
- profile_view
- whitepaper_view
- security_view

No IP address, wallet address, email, device fingerprint or user identifier is written into the community metrics record.

## Evidence classes
### Class A — First-party aggregate interaction
Website event counts. Useful for conversion trends, not proof of unique humans.

### Class B — Platform analytics
X, GitHub or other official platform analytics. Source-labelled.

### Class C — Contributor evidence
Public contributions, PRs, artwork, translations or campaign outputs.

### Class D — Independent public evidence
On-chain and third-party market data after Mainnet.

## KPI hierarchy
1. Monthly Active Contributors.
2. Returning contributors.
3. New contributors.
4. Community-created assets.
5. Trust-page conversion.
6. Qualified referral traffic.
7. Organic engaged accounts.
8. Raw followers/impressions.

## Anti-gaming rule
Never combine paid and organic reach without labeling. Never treat first-party click counts as holder, user or unique-human counts.
