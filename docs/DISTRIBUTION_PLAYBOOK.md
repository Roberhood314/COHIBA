# COHIBA Distribution Playbook v1.0

## Objective
Create repeatable distribution that moves people through:

**Discovery → Understanding → Participation → Contribution → Advocacy → Product/Token interaction**

Distribution must not depend on fake followers, paid engagement represented as organic, wash trading or speculative promises.

## Channel architecture

### X — Discovery layer
Official: https://x.com/hunhkcgy

Purpose:
- narrative distribution;
- memes;
- AI/human cultural commentary;
- build-in-public updates;
- community amplification.

Content mix:
- 50% culture/meme;
- 20% AI/human narrative;
- 15% build-in-public;
- 10% community work;
- 5% token/market facts.

### Website — Trust layer
Official: https://cohibameme.site

Purpose:
- convert curiosity into trust;
- explain project thesis;
- expose verification/security evidence;
- route visitors into contribution paths.

### GitHub — Builder layer
Official: https://github.com/Roberhood314/COHIBA

Purpose:
- technical credibility;
- issue/discussion-based participation;
- security/documentation contributions;
- public change history.

### Community real-time channel — Activation layer
Telegram/Discord is intentionally **not claimed as official until a canonical channel is created and linked from the website**.

When created:
- one official announcement channel;
- one discussion space;
- scam warning pinned;
- official-link verification page;
- clear moderation rules.

## Distribution loops

### Loop A — Meme loop
Create → community remixes → official account amplifies → new creators discover COHIBA → best work enters website/community archive.

### Loop B — Research loop
AI/human question → discussion → community insights → editorial post → shareable visual → new discussion.

### Loop C — Engineering trust loop
Ship real improvement → publish evidence → technical community reviews → corrections/feedback → stronger evidence → new technical advocates.

### Loop D — Contributor loop
Discover project → choose contribution path → contribution credited → contributor featured → contributor invites peers.

### Loop E — Partnership loop
Shared cultural or technical theme → joint content/integration → both audiences discover project → measurable referral traffic.

## Conversion surfaces
Every major distribution asset should have one primary CTA:
- Follow official X
- Read Project Profile
- Join / Contribute
- Review Security Evidence
- View GitHub
- Verify token state

Do not use ten competing CTAs in a single post.

## Campaign system

### Campaign 01 — The Human Signal
Question-led weekly series.
Goal: replies, quote posts, recurring participation.

### Campaign 02 — Machine vs Human
Visual/meme contest.
Goal: creator acquisition and remixing.

### Campaign 03 — Proof, Not Promise
One verifiable engineering/security fact per post.
Goal: technical trust and differentiation.

### Campaign 04 — Build With COHIBA
Monthly contributor recruitment.
Goal: builders, translators, researchers and moderators.

### Campaign 05 — Human First Stories
Community-submitted stories about work, creativity, identity and AI.
Goal: deepen emotional attachment beyond token speculation.

## 90-day distribution operating model

### Days 1–30 — Signal
- establish recognizable visual language;
- publish daily X content;
- launch Human Signal ritual;
- recruit first contributors;
- measure baseline engagement;
- create canonical community channel only when moderation is ready.

### Days 31–60 — Participation
- recurring meme/art challenges;
- community spotlight;
- localization;
- builder outreach;
- collaborative posts with aligned creators/projects;
- publish weekly public growth scorecard.

### Days 61–90 — Network
- ambassador pilot;
- regional/language leads;
- partner campaigns;
- integration conversations;
- creator collaborations;
- community-generated content becomes a meaningful percentage of output.

## Ambassador model
Ambassadors are contributors, not paid shillers.

Selection signals:
- sustained contribution;
- good conduct;
- ability to explain COHIBA accurately;
- original audience/community access;
- no history of fake engagement or misleading token promotion.

Ambassador responsibilities:
- translate;
- host discussions;
- create content;
- onboard contributors;
- report scams/misinformation;
- preserve canonical facts.

No ambassador may promise price, returns or guaranteed listing.

## Organic growth scorecard
Weekly:
- X impressions;
- profile visits;
- website visits;
- click-through rate;
- unique engaged accounts;
- organic reply rate;
- repost/quote rate;
- new contributors;
- returning contributors;
- community-created assets;
- GitHub stars/forks/issues/PRs;
- partner referrals;
- email/community joins once channels exist.

## Quality ratios
Prefer:
- unique engaged accounts / impressions;
- returning contributors / total contributors;
- community-created content / total content;
- direct/referral visits / paid visits;
- verified-human conversations / raw follower growth.

## Paid distribution policy
Paid promotion may be used for reach experiments, but:
- label sponsorships where required;
- never purchase fake followers;
- never buy fake engagement;
- never represent paid reach as organic traction;
- separate paid and organic KPIs.

## North-star metric
**Monthly Active Contributors (MAC)**

A contributor is someone who creates, translates, moderates, researches, develops, reviews or introduces a verifiable partnership.

This metric better reflects network strength than follower count alone.
