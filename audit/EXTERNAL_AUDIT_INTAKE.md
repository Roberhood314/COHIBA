**READY TO SEND TO AN INDEPENDENT REVIEWER**

Repository: `Roberhood314/COHIBA`

- production branch: `main`

## Mandatory reviewer questions
The reviewer should explicitly answer:
- Can Mainnet launch while default-deny controls remain false?
- Can launch authorization be bypassed?
- Can a second Mainnet mint be created after persistent lock?
- Can partial state/recovery create duplicate irreversible state?
- Can supply differ from 1,000,000,000 COH without detection?
- Can mint or freeze authority remain active while launch is marked final?
- Can the destination balance invariant be bypassed?
- Can metadata/canonical identity be substituted without detection?
- Can secrets leave server-side storage through API/log/error paths?
- Are dependency risks reasonably bounded by current controls?
- Is local security evidence materially representative of the production launch path?

## Required report format
The external report should contain:
- reviewer identity/entity;
- engagement dates;
- exact reviewed commit SHA;
- scope and exclusions;
- methodology;
- findings table;
- severity rubric;
- reproduction/evidence;
- remediation status;
- retest status;
- residual-risk statement;
- stable report URL or SHA-256.

## Finding lifecycle
Allowed states:
- SUBMITTED
- CONFIRMED
- FIXED
- RETESTED
- ACCEPTED_RISK
- NOT_APPLICABLE

A Critical/High finding cannot be closed only by maintainer assertion. Retest evidence is required where practical.

## Audit completion gate
COHIBA may change registry status from `NOT_COMPLETED` only when:
1. independent reviewer is identifiable;
2. report exists;
3. reviewed commit is known;
4. Critical/High findings are resolved or formally accepted with rationale;
5. required remediation has been re-reviewed;
6. report evidence is publicly verifiable.

Until all six are true:
**INDEPENDENT SECURITY AUDIT = PENDING_EXTERNAL**
